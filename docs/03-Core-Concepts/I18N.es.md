# Sistema de Internacionalización (i18n)

Tu aplicación habla inglés, español, y lo que quieras añadir.

## Archivos de Traducción

Los diccionarios viven en `src/i18n/*.json`.

**es.json**

```json
{
    "alerts": {
        "required": "Campo requerido",
        "email": "Email inválido"
    },
    "messages": {
        "welcome": "Bienvenido, {{name}}!"
    }
}
```

## Uso en Business Objects

Tienes acceso a `this.i18n`.

### 1. Traducción Simple

```typescript
const msg = this.i18n.t('alerts.required')
// "Campo requerido"
```

### 2. Interpolación (Variables)

Usa `{{variable}}` en el JSON.

```typescript
const msg = this.i18n.t('messages.welcome', { name: 'Eliab' })
// "Bienvenido, Eliab!"
```

### 3. Arrays y Objetos

También puedes recuperar estructuras completas.

```typescript
const alerts = this.i18n.t('alerts')
// Retorna el objeto completo de alertas
```

## ¿Cómo sabe el sistema qué idioma usar?

El idioma se define en 3 niveles de prioridad:

1.  **Variable de Entorno (`APP_LANG`)**: El idioma por defecto del servidor (e.g. `es`).
2.  **Configuración de Usuario**: (Futuro) Podríamos cargar el idioma desde el perfil del usuario `users.language`.

Actualmente, el framework carga el idioma definido en `.env` al inicio.
El soporte para multi-idioma "por request" (que cada usuario vea un idioma distinto al mismo tiempo) requeriría pasar una instancia de `i18n` personalizada en cada BO. La arquitectura actual soporta esto inyectando el servicio en el constructor.

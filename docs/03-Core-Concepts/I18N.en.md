# Internationalization System (i18n)

Your app speaks English, Spanish, and whatever else you add.

## Translation Files

Dictionaries live in `src/i18n/*.json`.

**en.json**

```json
{
    "alerts": {
        "required": "Field required",
        "email": "Invalid Email"
    },
    "messages": {
        "welcome": "Welcome, {{name}}!"
    }
}
```

## Usage in Business Objects

You have access to `this.i18n`.

### 1. Simple Translation

```typescript
const msg = this.i18n.t('alerts.required')
// "Field required"
```

### 2. Interpolation (Variables)

Use `{{variable}}` in the JSON.

```typescript
const msg = this.i18n.t('messages.welcome', { name: 'Eliab' })
// "Welcome, Eliab!"
```

### 3. Arrays and Objects

You can also retrieve full structures.

```typescript
const alerts = this.i18n.t('alerts')
// Returns the full alerts object
```

## How does the system know which language to use?

Language is defined with 3 priority levels:

1.  **Env Variable (`APP_LANG`)**: Server default language (e.g., `es`).
2.  **User Config**: (Future) We could load language from user profile `users.language`.

Currently, the framework loads the language defined in `.env` at startup.
Support for per-request multi-language (each user seeing different language simultaneously) works by injecting a localized service instance into the BO constructor.
